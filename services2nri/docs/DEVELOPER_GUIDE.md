# Services2NRI — Developer Guide

**Version:** 4.4.0  
**Stack:** PHP 8.0+, React 18, Vite 5, WordPress 6.0+

---

## Quick Start

### Prerequisites
- WordPress 6.0+ site (local or staging)
- PHP 8.0+
- Node.js 18+ (for builder SPA only)
- MySQL 5.7+ or MariaDB 10.3+

### Installation
1. Copy the entire `plugin/` folder to `wp-content/plugins/services2nri/`
2. Activate in WP Admin → Plugins
3. Plugin auto-creates all DB tables and seeds sample data on activation

### Development Setup
```bash
# Edit PHP files directly — no compilation needed for PHP
# For the builder SPA (s2nri-builder.js) only:
cd plugin/src-react
npm install
npm run dev        # Vite dev server (not used in production — builder loads from builder/)
npm run build      # Compiles to plugin/builder/s2nri-builder.js
```

## Adding a New API Endpoint

### 1. Add controller method
```php
// In the appropriate controller class in src/Api/Controllers/Admin/AdminControllers.php
// or create a new Phase5Controllers.php

class MyNewController extends \S2NRI\Api\Controllers\BaseController {

    // GET admin/my-resource
    public function index( Request $req ): void {
        $this->requireStaff(); // or requireManager() / requireAdmin()
        global $wpdb;
        $rows = $wpdb->get_results(
            "SELECT * FROM {$wpdb->prefix}s2nri_my_table WHERE deleted_at IS NULL",
            ARRAY_A
        );
        Response::json( [ 'items' => $rows ?: [] ] );
    }

    // POST admin/my-resource
    public function store( Request $req ): void {
        $this->requireStaff();
        $name = sanitize_text_field( $req->input('name', '') );
        if ( ! $name ) {
            Response::json( [ 'error' => 'Name is required.' ], 422 );
            return;
        }
        global $wpdb;
        $wpdb->insert( $wpdb->prefix . 's2nri_my_table', [
            'name'       => $name,
            'created_at' => current_time('mysql'),
        ] );
        Response::json( [ 'success' => true, 'id' => $wpdb->insert_id ] );
    }
}
```

### 2. Register in Dispatcher
```php
// In src/Api/Dispatcher.php, inside the route registration block:
$this->add('GET',  'admin/my-resource',       MyNewController::class, 'index',  true);
$this->add('POST', 'admin/my-resource',        MyNewController::class, 'store',  true);
$this->add('PUT',  'admin/my-resource/{id}',   MyNewController::class, 'update', true);
$this->add('DELETE','admin/my-resource/{id}',  MyNewController::class, 'destroy',true);
```

### 3. Auto-load the class
```php
// At the top of services2nri.php in the autoloader section:
require_once S2NRI_DIR . 'src/Api/Controllers/Admin/Phase5Controllers.php';
```

## Adding a Database Migration

All migrations go in `src/Installer.php` → `runMigrations()`.

```php
// Example: add a new column to services table
$svc_cols = $wpdb->get_col( "SELECT COLUMN_NAME FROM information_schema.COLUMNS
    WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = '{$p}s2nri_services'" );
if ( ! in_array( 'my_new_column', $svc_cols ) ) {
    $wpdb->query( "ALTER TABLE `{$p}s2nri_services`
        ADD COLUMN `my_new_column` VARCHAR(255) DEFAULT NULL
        COMMENT 'Added in v4.5.0: description of what this stores'" );
}
```

**Rules:**
- Always guard with `IF NOT EXISTS` or column check — migrations must be idempotent
- Always bump `S2NRI_VERSION` in `services2nri.php` when adding migrations
- Add a comment with the version the column was added
- Never use `ALTER TABLE ... DROP COLUMN` in migrations (breaking change)
- Never rename columns (use ADD new + deprecate old)

## Adding a New Builder Tab (React)

### 1. Create the page component
```jsx
// src-react/src/pages/MyNewPage/index.jsx
import { useState, useEffect } from 'react'
import api from '../../utils/api'
import { useToast } from '../../hooks/useToast'
import { Button, Spinner, ToastContainer } from '../../components/common'

export default function MyNewPage() {
  const [data, setData] = useState(null)
  const [loading, setLoading] = useState(true)
  const { toasts, toast } = useToast()

  useEffect(() => {
    api.get('admin/my-resource')
      .then(res => setData(res))
      .catch(err => toast.error(err.message))
      .finally(() => setLoading(false))
  }, [])

  if (loading) return <Spinner />

  return (
    <>
      <ToastContainer toasts={toasts} />
      <div className="page-header">
        <h1>My New Feature</h1>
      </div>
      {/* ... your UI ... */}
    </>
  )
}
```

### 2. Register tab in App.jsx
```jsx
// src-react/src/App.jsx — add to TABS array:
{ id: 'my-new', label: '🔧 My Feature', component: MyNewPage }
```

### 3. Rebuild
```bash
cd src-react && npm run build
```

## Debugging

### PHP API errors
```php
// In any controller, use error_log() for server-side debugging:
error_log('[S2NRI] MyController::myMethod — ' . print_r($someValue, true));
// Logs appear in wp-content/debug.log (if WP_DEBUG_LOG=true)
```

### Enable WP_DEBUG
```php
// In wp-config.php:
define('WP_DEBUG', true);
define('WP_DEBUG_LOG', true);
define('WP_DEBUG_DISPLAY', false); // Never display to users in production
```

### Check DB queries
```php
// Temporarily add to any controller:
$wpdb->show_errors();
// ... your query ...
if ($wpdb->last_error) {
    error_log('[S2NRI] SQL error: ' . $wpdb->last_error);
    error_log('[S2NRI] Last query: ' . $wpdb->last_query);
}
```

### API debugging from browser console
```javascript
// On any page with S2NRI_CONFIG or S2NRI_BUILDER:
const cfg = window.S2NRI_CONFIG || window.S2NRI_BUILDER;
fetch(`${cfg.apiBase || cfg.base}/admin/services`, {
  headers: { 'X-WP-Nonce': cfg.nonce },
  credentials: 'include'
}).then(r => r.json()).then(console.log)
```

### Check settings values
```sql
-- In MySQL:
SELECT setting_key, setting_value, is_public
FROM wp_s2nri_settings
WHERE setting_key LIKE 'hero_%' OR setting_key LIKE 'marquee_%'
ORDER BY setting_key;
```

### Verify section toggle is working
```sql
-- Check is_visible + is_active sync:
SELECT id, type, title, is_visible, is_active, sort_order
FROM wp_s2nri_service_sections
WHERE service_id = 1
ORDER BY sort_order;
```

## Common Issues and Solutions

### Hero not updating after builder save
1. Clear CDN cache (Cloudflare → Purge Everything)
2. Check WP object cache: `wp_cache_flush()` (or restart Redis/Memcached)
3. Verify `s2nri_settings` table has the expected keys:
   ```sql
   SELECT * FROM wp_s2nri_settings WHERE setting_key = 'hero_heading_1';
   ```
4. Check `Cache-Control: no-store` header is being sent by SEO.php

### Builder SPA shows blank / infinite spinner on Marquee tab
1. Open browser DevTools → Network → look for failed requests to `/wp-json/s2nri/v1/admin/services/N`
2. Check response: 401 = auth failed (try refreshing the builder page), 404 = service not found
3. Verify columns exist: `SHOW COLUMNS FROM wp_s2nri_services LIKE 'marquee_settings'`
4. If column missing: deactivate and reactivate plugin (triggers migration)

### Section toggles not reflecting in frontend
1. Verify `is_visible` column: `SHOW COLUMNS FROM wp_s2nri_service_sections LIKE 'is_visible'`
2. Check builder toggle response in DevTools: should return `{"success":true,"is_visible":0,"is_active":0}`
3. Clear any page cache

### Portal (/s2nri-admin/) shows stale service count
- Backend returns both `total` (57) and `active_count` (49). The portal JS reads `total` for
  the list count display. Dashboard stat reads `active_count`. This is correct behavior.

## Version Bumping Procedure

When making any code change that goes to production:

1. Edit `services2nri.php`:
   - Header: `Version: X.Y.Z`
   - Constant: `define('S2NRI_VERSION', 'X.Y.Z')`

2. If any DB changes: add migration to `Installer::runMigrations()` with column guard

3. Add entry to `docs/CHANGELOG.md`

4. If builder React source changed: `cd src-react && npm run build`

5. Test: deactivate → reactivate plugin on staging site

6. Verify migration ran: `SELECT option_value FROM wp_options WHERE option_name = 's2nri_db_version'`

## Rollback Procedure

### Quick rollback (same session)
```bash
# On the server:
cp -r /path/to/snapshots/v4.3.26-original/ /wp-content/plugins/services2nri/
# In WP Admin: Deactivate → Activate plugin
```

### Safe rollback (any version)
1. Deactivate plugin in WP Admin
2. Replace plugin directory with previous version files
3. Reactivate plugin
4. All migrations are additive — old code works with new DB columns (they have DEFAULT NULL)
5. No data loss possible — we never DROP columns or DELETE rows in migrations

## Security Checklist for New Code

Before any PR or deployment:

- [ ] All user input sanitized: `sanitize_text_field()`, `sanitize_key()`, `wp_kses_post()`, `esc_url_raw()`
- [ ] All DB writes use `$wpdb->prepare()` with typed placeholders (`%s`, `%d`, `%f`)
- [ ] All endpoints have appropriate auth check: `requireStaff()` / `requireManager()` / `requireAdmin()`
- [ ] All HTML output escaped: `esc_html()`, `esc_attr()`, `esc_url()`, `wp_json_encode()`
- [ ] No raw `$_GET`/`$_POST` used without sanitization
- [ ] No `SELECT *` on large tables (explicit column list prevents memory overflow)
- [ ] `$wpdb->last_error` checked after every write operation
- [ ] New routes added with `true` (protected) unless explicitly public
